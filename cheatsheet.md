- . (одна точка) — текущий каталог (папка, в которой вы сейчас находитесь).
- .. (две точки) — родительский каталог (папка на один уровень выше).
- ~ (тильда) — домашний каталог текущего пользователя (например, /home/username или C:\Users\username).
- - (дефис/минус) — предыдущий каталог (возврат в папку, в которой вы были до этого, используется с командой cd -).

- pwd                      # где я сейчас?
- cd ~                     # домой
  cd - (МИНУС) возвращает в предыдущую папку, где ты был до этого. Два раза подряд — прыжки туда-обратно. Удобно, когда работаешь в двух местах.
- mkdir -p study/week1     # создать папку study и внутри неё week1
- cd study/week1           # относительный путь

- touch a.txt b.txt        # создать два пустых файла

- echo "привет" > a.txt    # записать текст в файл
- cat a.txt                # показать файл
- cp a.txt c.txt           # скопировать

- mv b.txt renamed.txt     # переименовать
mv — это сокращение от move, «переместить». Переименование — частный случай перемещения.
  Для Linux это одна и та же операция: файл меняет полный путь. Путь состоит из папки и имени:
mv может поменять любую часть пути:
Команда	Что меняется	Итог
  mv cat.jpg dog.jpg	только имя, папка та же	переименование
  mv cat.jpg ../study/	только папка, имя то же	перемещение
  mv cat.jpg ../study/dog.jpg	и папка, и имя	перемещение с переименованием
mv молча перезаписывает. Если в папке назначения уже есть файл с таким же именем, он будет заменён без предупреждения и без корзины. Чтобы Linux спрашивал, добавляй -i:
Если файл там уже есть, появится вопрос overwrite?. Для cp то же самое: cp -i.

## 1. Три потока
У каждой команды есть три «трубы»:

Номер	Название	Что это	По умолчанию
0	stdin	вход, откуда команда читает	клавиатура
1	stdout	обычный вывод, результат	экран
2	stderr	ошибки	тоже экран
Обычный вывод и ошибки — два разных потока. На экране они смешиваются, и кажется, что это одно и то же. Но перенаправлять их можно по отдельности. Отсюда и ответ на задание 3.
Аналогия: у команды есть два выхода, «готовая продукция» (1) и «брак» (2). Оба по умолчанию сыплются на один стол, на экран.
- «>» — вывод в файл (с перезаписью)
Вывод не попадает на экран, а записывается в etc.txt. Если файла нет, он создаётся. Если файл был, его содержимое стирается без вопросов. Корзины нет, -i нет.
- «>>» — дописать в конец
То же самое, но старое содержимое остаётся, а новое добавляется в конец.
echo просто выводит текст, который ты ему дал. Вместе с >> им удобно дописывать строки в файл.
Чтобы не путать: один > перезаписывает, два >> добавляют.
- 2> — ошибки в файл
Цифра 2 — это номер потока ошибок. Ошибка уходит в файл, на экране пусто.
Можно разделить оба потока сразу:
Результат попадёт в ok.txt, а ошибка — в err.txt.
Обрати внимание: > — это на самом деле сокращение от 1>.
- /dev/null — «чёрная дыра»
Это специальный файл: всё, что в него пишешь, исчезает.
find по всей системе выдаёт сотни ошибок Permission denied. Если отправить их в /dev/null, на экране останутся только найденные файлы. Это пригодится в среду, когда дойдём до find.
- «|» — конвейер (pipe)
cat /etc/passwd | less
| передаёт вывод одной команды на вход следующей, а не в файл. Первая команда выдаёт текст, вторая его обрабатывает. Промежуточных файлов нет.
	Куда уходит вывод
«>»	в файл
|	в другую команду
На этом держится вся неделя. Скоро будут цепочки вроде:
grep "install" /var/log/dpkg.log | wc -l
Здесь grep находит строки, а wc -l их считает. Это и есть критерий недели: «одной командой нашёл строки в логе и посчитал».
- Ловушки
«>» вместо >> — молча стёр файл.
cat file.txt > file.txt — файл станет пустым. Bash сначала очищает файл для записи и только потом запускает cat, а тому уже нечего читать.
«>» file перехватывает только stdout. Ошибки всё равно вылезут на экран, для них нужен 2>.
