- Через двойное вертикальное перечеркивание || — вторая команда выполнится только если первая завершилась ошибкой.
	• Пример: команда1 || echo "Что-то пошло не так"

## 1. Три потока
- У команды два выхода: 1 — результат, 2 — сообщения об ошибках. Они работают независимо: команда может писать в один, в другой, в оба сразу или ни в один.
- «>» и 2> — это не команды, а операторы перенаправления.
У каждой команды есть три «трубы»:

Номер	Название	Что это	По умолчанию
0	stdin	вход, откуда команда читает	клавиатура
1	stdout	обычный вывод, результат	экран
2	stderr	ошибки	тоже экран
Обычный вывод и ошибки — два разных потока. На экране они смешиваются, и кажется, что это одно и то же. Но перенаправлять их можно по отдельности. Отсюда и ответ на задание 3.
Аналогия: у команды есть два выхода, «готовая продукция» (1) и «брак» (2). Оба по умолчанию сыплются на один стол, на экран.
- «>» — вывод в файл (с перезаписью)
Вывод не попадает на экран, а записывается в etc.txt. Если файла нет, он создаётся. Если файл был, его содержимое стирается без вопросов. Корзины нет, -i нет.
- «>>» — дописать в конец
То же самое, но старое содержимое остаётся, а новое добавляется в конец.
echo просто выводит текст, который ты ему дал. Вместе с >> им удобно дописывать строки в файл.
Чтобы не путать: один > перезаписывает, два >> добавляют.
- 2> — ошибки в файл
Цифра 2 — это номер потока ошибок. Ошибка уходит в файл, на экране пусто.
Можно разделить оба потока сразу:
Результат попадёт в ok.txt, а ошибка — в err.txt.
Обрати внимание: > — это на самом деле сокращение от 1>.
- /dev/null — «чёрная дыра»
Это специальный файл: всё, что в него пишешь, исчезает.
find по всей системе выдаёт сотни ошибок Permission denied. Если отправить их в /dev/null, на экране останутся только найденные файлы. Это пригодится в среду, когда дойдём до find.
- «|» — конвейер (pipe)
cat /etc/passwd | less
| передаёт вывод одной команды на вход следующей, а не в файл. Первая команда выдаёт текст, вторая его обрабатывает. Промежуточных файлов нет.
	Куда уходит вывод
«>»	в файл
|	в другую команду
На этом держится вся неделя. Скоро будут цепочки вроде:
grep "install" /var/log/dpkg.log | wc -l
Здесь grep находит строки, а wc -l их считает. Это и есть критерий недели: «одной командой нашёл строки в логе и посчитал».
- Ловушки
«>» вместо >> — молча стёр файл.
cat file.txt > file.txt — файл станет пустым. Bash сначала очищает файл для записи и только потом запускает cat, а тому уже нечего читать.
«>» file перехватывает только stdout. Ошибки всё равно вылезут на экран, для них нужен 2>.
## grep и wc
- grep — оставляет только строки, в которых есть нужный текст
Схема:
файл ──► grep 'apple' ──► выход 1: только строки, где есть "apple"
                     └──► выход 2: ошибки (например, нет такого файла)
Важно: grep ищет кусок текста, а не слово целиком. По apple найдётся и pineapple.
Регистр учитывается: apple и Apple для grep разные слова.
Шаблон бери в кавычки '...', особенно если в нём есть пробелы.
Если ничего не нашлось, grep ничего не выводит, и это не ошибка.
Основные ключи:
Ключ	Что делает
- «-i»	не различать большие и маленькие буквы
- «-v»	наоборот: строки, где этого текста нет
- «-n»	показать номер строки
- «-c»	вместо самих строк вывести их количество
- wc — считает строки, слова и символы (word count)
Команда	Что считает
wc файл	строки, слова и байты
- wc -l файл	только строки (чаще всего нужно именно это)
- wc -w файл	слова
- wc -c выводит количество байт в указанном файле или в тексте, который передали ей на вход
- wc -l считает строки. файл выводит 5 файл, то есть число и имя. Если данные пришли через |, имени файла нет, выводится просто 5.
Связка через |
wc -l fruits.txt          →  7 fruits.txt
cat fruits.txt | wc -l    →  7
grep 'install' /var/log/dpkg.log | wc -l
   │                               │
   └ оставил нужные строки ──────► └ посчитал их
Это то же самое, что grep -c 'install' /var/log/dpkg.log. Полезно знать оба способа: | wc -l можно поставить после любой команды, а не только после grep.
## sort / uniq / cut и find 
Sort: сортирует строки 
- sort файл     # по алфавиту
- sort -r	    # в обратном порядке (reverse)
- sort -n	    # как числа: 9 < 10. Без -n будет «10» < «9», потому что строки сравниваются по первому символу
uniq: убирает повторы
- Главная ловушка: uniq убирает только одинаковые строки, которые стоят подряд. Поэтому почти всегда пишут sort | uniq: сначала сортировка собирает одинаковые строки вместе.
- uniq -c пишет перед строкой, сколько раз она встретилась (count).
Связка, которую надо запомнить: sort | uniq -c | sort -rn выдаёт рейтинг «что встречается чаще всего».
- sort + uniq -u (строки без повторов)
cut: вырезает колонку
- cut -d: -f1 файл означает «разделитель :, взять поле 1». Пробел как разделитель пишется в кавычках: -d' '
- «-d» — разделитель (delimiter), -f — номер поля (field), можно перечислить: -f1,7.
Удобно на /etc/passwd, где поля разделены :: alex:x:1000:1000:alex:/home/alex:/bin/bash
 	                                          1   2  3    4    5      6          7
find: ищет файлы по имени и типу
- find ГДЕ  -name "ЧТО"    может быть ещё -type f (файлы) d (директории) без find ищет всё подряд
- find ~/study -name "*.txt" — все .txt внутри ~/study, включая подпапки. Шаблон бери в кавычки, иначе bash сам подставит вместо * имена файлов из текущей папки (* Звёздочка значит «что угодно». ).
- «-iname» — то же самое, но без учёта регистра.
- «-type f» — только файлы, -type d — только папки.
Поиск от / выдаёт кучу Permission denied в поток 2, их убирают через 2>/dev/null (это ты уже умеешь).
Чем find отличается от grep: grep ищет текст внутри файлов, а find ищет файлы по имени. Во вторник ты столкнулся с этим, когда grep 'ssh' /usr/bin выдал «Is a directory».

Ловушки
- useradd без -m и -s создаст пользователя без домашней папки и с /bin/sh. Ключи обязательны. (Есть ещё adduser, он задаёт вопросы и делает всё сам, но на собеседованиях и в скриптах встречается useradd.)
- ⚠️ usermod -G без -a не добавляет группу, а заменяет весь список групп. Если сделать так с alex, он вылетит из группы sudo и потеряет права администратора. Всегда пиши -aG (a = append, «дописать»), и с alex сегодня ничего не делаем.
- Значение идёт сразу за своим ключом, как в среду: -s /bin/bash, -G devs. В -aG devs значение devs относится к G, поэтому G стоит последней.
- Новая группа начинает работать только после нового входа пользователя (su - bob заново).
- Пароль при вводе не отображается, даже звёздочками. Это нормально.
Контрольные вопросы
1 Где хранятся пароли и почему не в /etc/passwd?
  В /etc/shadow, который может читать только root. /etc/passwd открыт всем, потому что его читают многие программы, например чтобы показать имя владельца файла в ls -l.
2 Чем usermod -G devs bob опасно отличается от usermod -aG devs bob?
  Без -a список групп bob заменится на одну devs, и все остальные его группы пропадут. С -a devs добавится к уже имеющимся.
3 Что значит /usr/sbin/nologin в 7-м поле?
  Служебный пользователь, под ним нельзя войти в систему.
4 Какой пароль спрашивает sudo, а какой su - bob?
  sudo спрашивает пароль того, кто вводит команду (твой). su - bob спрашивает пароль bob.
5 Что сделает sudo useradd bob без ключей и чем это плохо?
  Создаст пользователя без домашней папки и с /bin/sh. Войти под ним будет неудобно, и своих файлов ему хранить негде.
## права доступа (rwx, chmod, chown)
-rw-r--r--  1  root  root  2345  ноя 11  /etc/passwd
│└┬┘└┬┘└┬┘     └┬─┘  └┬─┘
│ │  │  │       │     └─ группа файла
│ │  │  │       └─────── владелец файла
│ │  │  └─ o (others): все остальные
│ │  └──── g (group): участники группы файла
│ └─────── u (user): владелец
└───────── тип: - файл, d папка
Девять символов делятся на три тройки: владелец, группа, остальные. Каждая тройка всегда идёт в порядке r w x, а - на месте буквы значит «этого права нет».

- r (read)    для файла: читать содержимое (cat)    для папки:   видеть список имён (ls)
- w (write)   для файла: менять содержимое (>>, редактор)    для папки:   создавать, удалять и переименовывать файлы внутри
- x (execute)   для файла: запускать как программу (./script.sh)    для папки:   входить (cd) и обращаться к файлам внутри
 ⚠️ Удалить файл можно или нельзя в зависимости от прав на папку (w), а не на сам файл.

Какую тройку проверяет система
Ты владелец файла?   ──да──► берётся ТОЛЬКО тройка u
        │нет
Ты в группе файла?   ──да──► берётся ТОЛЬКО тройка g
        │нет
        └──────────────────► тройка o
 Проверка останавливается на первом совпадении. root ограничений не имеет.
 
 chmod буквами
 Схема: chmod КОМУ ДЕЙСТВИЕ ПРАВА файл
кому: u владелец, g группа, o остальные, a все
действие: + добавить, - убрать, = установить ровно так
- chmod u+x script.sh        владельцу добавить x
- chmod o-r notes.txt        остальным убрать r
- chmod g=rw notes.txt       группе ровно rw
- chmod u=rwx,g=rx,o= f      сразу все три тройки (o= значит «ничего»)
Буквы «кому» можно писать вместе: chmod ug+x backup.sh  Ещё вариант через запятую: chmod u+x,g+x backup.sh.

   chmod числами
Каждое право имеет вес: r = 4, w = 2, x = 1. Веса в тройке складываются, получается одна цифра на тройку.
rwx = 4+2+1 = 7      r-x = 4+0+1 = 5      rw- = 4+2+0 = 6
r-- = 4              --- = 0
число	права	   где встречается
755	  rwxr-xr-x	   папки, скрипты
644   rw-r--r--	   обычные файлы
700	  rwx------	   личная папка
600	  rw-------	   секретный файл (ключи)
750	  rwxr-x---	   домашние папки в Ubuntu 26
Проверить себя числом: stat -c '%a %A %U %G' файл покажет, например, 644 -rw-r--r-- alex alex.

chown: сменить владельца или группу
- sudo chown bob file            владелец bob
- sudo chown bob:devs file       владелец bob, группа devs
- sudo chown :devs file          только группа
- sudo chown -R bob:devs dir     то же для папки со всем содержимым
Отдать файл другому может только root, поэтому chown всегда идёт через sudo. А chmod для своего файла работает без sudo.
