# Потоки и перенаправления
есть два потока, исполнение команды и ошибка 
«>» перенаправление с перезаписью
«>>» перенаправление добавление 
2> перенаправление ошибок, полезно с /dev/null чтобы все ошибки улетали в этот файл
1 — результат (stdout), 2 — ошибки (stderr), работают независимо. 
«|» передаёт вывод в другую команду (> пишет в файл, | отдаёт команде). 
Пример: cat /etc/passwd | head -n 5

# grep и wc
## grep поиск по словам, оставляет строчки с нужным текстом 
Ключи -i -v -n -c
«-i» не различать большие и маленькие буквы
«-v» наоборот: строки, где этого текста нет
«-n» показать номер строки
«-c» вместо самих строк вывести их количество
## wc считает строки слова и символы 
«-l» строки, -w слова, -c байты
grep install /var/log/dpkg.log | wc -w

# Права (сюда твоя фраза про x у папки)
отображаются в одну строку буквами r w x и символом - и имеют численный эквивалент, суммируются по тройкам и отображаются числом 
r чтение 4
w запись 2
x исполнение 1 
«-» нет прав
например rwxr-x-wx или 753
означает что владелец может и читать и записывать и исполнять файл, группа может читать и исполнять остальные могут записывать и исполнять
тройки: владелец / группа / остальные. Сначала «кто ты для файла», потом читается одна тройка;
у папки: r — список имён, w — создавать и удалять внутри, x — входить.
chmod (только владелец) и chown (только root)

# Проект недели: команды этапов A и B
## Проект недели: папка, куда не войдёт чужой

**Задача:** у dana личная папка, у команды devs общая, остальных не пускает.

### Этап A — личная папка dana
- создать пользователя: `sudo useradd -m -s /bin/bash dana`
- задать пароль: `sudo passwd dana`
- создать папку: `sudo mkdir -p /srv/dana-box`
- отдать dana: `sudo chown dana:dana /srv/dana-box`
- права только владельцу: `sudo chown 700 /srv/dana-box`
- итог `ls -ld`: `ls -ld /srv/dana-box`
- drwxr-xr-x 2 700 dana 4096 Nov 15 04:44 /srv/dana-box

| Кто | Команда | Результат |
|---|---|---|
| dana | `ls /srv/dana-box` | ✅ |
| kate | `ls /srv/dana-box` | ❌ Permission denied |
| alex без sudo | ls /srv/dana-box |  Permission denied |
| root (sudo) | ls /srv/dana-box |  ✅ |

### Этап B — командная папка devs
- создать папку: sudo mkdir /srv/devs-team
- владелец root, группа devs: sudo chown root:devs /srv/devs-team
- права владельцу и группе: sudo chmod 770 /srv/devs-team ← этой строки сейчас нет
- добавить dana в devs: sudo usermod -aG devs dana

| Кто | Команда | Результат |
|---|---|---|
| bob (devs) | -u bob touch /srv/devs-team/plant.txt | ✅ |
| kate (не в devs) | -u kate ls /srv/devs-team |  Permission denied |

### Вывод
- (твоя фраза про 777 и папку 700)
у папки dana-box права 700 для kate это третья тройка ---, нет x
- ошибка, которую поймал: `chown 700` вместо `chmod 700` → владельцем стал UID 700, правильно sudo chmod 700 /srv/dana-box
- итог ls -ld: drwxr-xr-x 2 700 dana → drwx------ 2 dana dana ...
chmod = mode, режим, то есть права (700, u+x) chown = owner, владелец, то есть кто (dana:dana)
